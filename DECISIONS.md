# PokéLib product and technical decisions

## Final search and surface polish — 2026-09-10 (current)

- Unquoted `+` is AND between independently correlated same-set clauses on one current variant. Metadata applies globally. Composition clauses require actual indexed members and cannot fall back to title mentions. No-plus plans and previously saved v1 collection definitions keep their existing semantics. Quoted metadata preserves literal plus signs, including during collection canonicalization.
- The plan adds optional clauses and same-slot Mega equivalents derived from pinned Dex required items/moves. Base species searches remain exact. A maximum of six nonempty clauses bounds SQL work; duplicate conditions need not occupy distinct slots, and an empty trailing clause is ignored during typing. No raw snapshots/indexed history are rewritten.
- D1 repeats anchored indexed predicates before pagination/grouping. PostgreSQL has an append-only private matcher migration with helper permissions revoked. Existing owner scopes, capability resolution, current/history rules and concurrency guards remain.
- Preserve the 250 ms text debounce. The request owns a separate 200 ms feedback timer and abort signal; cleanup runs at layout-effect boundaries so stale results/errors cannot replace current state. Keep prior rows visible during refresh and cancel obsolete requests. Only selection stays blocked until its query scope is current.
- Define shared charcoal surface levels in globals.css and apply them consistently to navigation, workspace, cards, dialogs, controls and selectors. Preserve compact geometry and restrained green accents; no decorative loading animation.
- QA uses the existing isolated local database. A localhost-only test proxy delays responses and forwards Vite HMR; it is a test script, never an application runtime capability. Hosted latency, physical-device and full assistive-tech performance remain unmeasured.

## Pre-beta usability and rebranding — 2026-09-10 (prior checkpoint; invariants retained)

- **PokéLib** is the display name; **pokelib** is used for new technical names. Existing Sites project/URL, database identities and migration filenames stay unchanged. View preferences read the historical teamvault-view key as fallback; legacy X-TeamVault-Profile requests still work. Source is pokelib-source.tar with a byte-identical old-URL alias. AGPL and upstream notices remain.
- Hide singleton variant counts and ordinary initial-revision badges. Keep numbered entries inside History, multi-revision indicators and expandable multi-variant families. No snapshots or revision identities are removed.
- One focused format search spans the canonical registry and generations. Match token prefixes rather than arbitrary substrings (e.g. 'ub' must not match the middle of 'doubles'). Custom / Other explicitly exposes generation/battle context. Pokémon advanced filters are optional; existing pools, raw fields, notes and keyboard completion stay intact.
- Showdown backup format recognition is restricted to a known leading bracketed token, with official -box support. Unknown tokens remain title text and the format stays Unknown, even when a default generation exists. Headerless imports retain explicitly chosen format/context. No historical imported records are automatically rewritten to repair previous guesses.
- Filter/collection cleanup uses the existing ID-only family selection and five-family deletion API. One confirmation includes the selected count/query. It deletes entire matching families including nonmatching siblings. Selection is reset on query changes; stale asynchronous select-all results are aborted.
- **Delete All** lives only under Settings → Danger Zone. Review freezes all owned family IDs and currently shared collection IDs (paged reads), then requires exact DELETE ALL. Revoke reviewed collection links first using the existing idempotent owner-checked revoke API, then reuse durable family-deletion chunks. Tags and saved collection definitions survive. No purge-specific database schema or unrestricted delete endpoint is added.
- New families/newly shared collections created elsewhere after review are outside the frozen scope; current variants of selected families are included. The operation is not one global transaction. A revocation or family chunk failure keeps completed effects; retry continues in the open dialog. Closing reports exact deleted/revoked counts; reload resumption remains deferred. Selection remains bounded at 10,000 families.
- Destructive browser QA uses POKELIB_QA=1 and .artifacts/prebeta/state only. The override is development-only; normal local .wrangler/state and production are unaffected. The fixture script verifies that server family IDs belong to that disposable database before writing.

Older sections below retain historical decisions; implemented features and the current scope above take precedence.

## PokéPaste import — 2026-09-10

- Import is an authenticated preview operation, followed by the existing explicit Import confirmation and chunked writes. It never creates a team just because a URL is pasted.
- Construct the fetch URL from a validated 16-digit hex ID on the exact HTTPS pokepast.es host. Do not follow redirects or forward cookies/auth headers. Bound both response headers and actual streamed bytes, use a timeout, validate JSON shape and keep Showdown parsing limits. This is not a general URL-fetching service.
- Preserve title, author, URL and notes when supplied. Named source type is PokéPaste in both adapters; optional long metadata is bounded with visible warnings. Import time must not become Team Date. Unknown format remains unknown until the user chooses one.
- Use the official /json read endpoint. No external key or publishing dependency. The live-service smoke test is separate from deterministic tests so upstream outages do not make the normal suite flaky.

## Team families and variants — 2026-09-10

- A family is the conceptual team; a variant is an intentional alternate build; history records changes to one variant. These concepts must remain distinct. Existing team IDs remain variant IDs and old snapshot rows are untouched.
- Legacy teams are virtual Main families (family_id null, effective family ID = team ID). The first sibling lazily materializes team_families and attaches the original row. Sibling names are case-insensitively unique. Clone copies the exact selected snapshot's raw/original text, notes, parsed data, comment and private authoring flags into revision 1, with fresh identities and no cross-variant parent. Creation has an owner-scoped retry receipt.
- Family title is synchronized into sibling metadata/title/search tokens by an explicit atomic rename. Variant format/tags/provenance/date can differ. Normal Save cannot rename a materialized family; use its detail heading. Save/new history/restore keep the existing three-token stale-write guards.
- The library groups matching variants in SQL before snapshot joins; expansion is separately paginated and honors the active search. A matching representative is Main when available, otherwise the most recently modified matching variant. Family counts and bulk selection are conceptual-family counts.
- Bulk metadata resolves all selected siblings before confirmation and freezes their IDs; it explicitly includes siblings outside the query. Family deletion is a separate five-family atomic, replay-safe operation. Deleting a variant never removes siblings; deleting the final materialized variant is blocked even through old deletion APIs.
- Existing team links remain variant-scoped, including numbered history. Public projections add only the shared variant's name/description, never sibling IDs/counts or private authoring flags. Showdown exports remain ordinary text, not a lossless family/history backup.
- PostgreSQL uses a transaction advisory write lock per owner before delegating to older RPCs. This deliberately serializes one owner's mutations to cover first-family materialization and avoid inverted family/team lock order; different owners can write independently. D1 batches retain atomic guards. Revisit lock granularity only with measured concurrency demand.
- SQLite migrations are additive and backed up locally before application. Drizzle 0.31's generated ADD COLUMN omitted ON DELETE CASCADE and its expression-index SQL incorrectly split commas; both generated SQL statements were corrected and exercised by adapter/migration tests. Inspect generated SQL rather than trusting schema declarations alone.

## Builder usability and current Save — 2026-09-09

These decisions supersede earlier statements that every edit creates an immutable snapshot.

- **Editable current, frozen history.** Save updates only the current numbered version. Save as new version preserves it and creates the next current version, with an optional comment. Historical editing/restoring always creates a new version; the pointer can never rewind to make an old row editable. Save retains version identity, creation date, parent, original import text and comment while updating authored raw text and notes.
- **Conflicts are explicit.** Both actions require the current version ID, snapshot edit_revision (legacy fallback: ID), and team updated_at. D1 checks all three inside its atomic batch; PostgreSQL locks the team and checks them in the RPC. Updates receive a fresh revision and a strictly increasing modified timestamp. Current search terms are replaced transactionally. Existing snapshots are not rewritten by the append-only migrations.
- **Sharing follows version semantics.** A living link follows current Save/new versions. A numbered link follows edits while that version is current and becomes fixed when it is historical. It still authorizes the conceptual team's other numbered versions.
- **Showdown aliases and identities.** Use installed official Dex aliases, with fallback-only competitive extensions (cc → Close Combat). Genuine exact names outrank aliases, which outrank prefixes/substrings. Normalize and deduplicate all Hidden Power variant IDs before rendering; variants obey the active query.
- **Battle-form presentation is a projection.** Select useful single-parent forms with an available item/move trigger using Showdown metadata. Canonical storage uses the starting species and required trigger; Crowned Iron Head displays as Behemoth Blade/Bash. Display transformed base stats without rewriting unchanged imported raw text. Multi-parent and pure transient battle/Tera states remain excluded. Z crystals alone do not imply Arceus forms.
- **Authored defaults have provenance.** Newly authored Gen 9 sets use required Tera type or primary type while auto-managed. Manual/imported values remain authoritative. New authored sets auto-zero Attack after four known nonphysical moves, or explicit Save of a partial nonphysical set; a physical move restores 31 only when PokéLib managed the zero. Never auto-zero Special Attack. Gen 1/2, Hidden Power and unknown moves are excluded from smart IV defaults.
- **Persist authoring flags privately.** Optional set_editing belongs to snapshots, copies into versions/restores and follows slot identities. Imports and legacy snapshots have no automatic flags. Raw changes drop provenance for changed blocks; unchanged/reordered blocks retain theirs. This metadata is absent from Showdown exports and shared projections.
- **Measured responsiveness.** Cache catalogs by generation/National Dex availability, warm catalogs during draft idle time, warm learnsets after species selection, render 40 selector rows initially with Show more, and reuse confirmed save responses instead of fetching the team again. Keep raw reconciliation safeguards. Optional ?profile=1 timings stay in browser console/performance entries and transmit no telemetry.
- **Focused scope.** No external Supabase setup, special-mod parity, PokéPaste, folders or unrelated product work. Compatibility migrations cover both retained storage adapters.

## Showdown integration — 2026-09-08/09

These decisions supersede older approximate-learnset and fixed-title descriptions below.

- **AGPL and focused reuse.** The user explicitly authorized open-source/AGPL work. PokéLib is AGPL-3.0-only, retaining MIT notices for MIT portions. Adapt Showdown's search traversal, keyboard and nature/default behavior into PokéLib React components. Do not import the Preact client, simulator or Showdown's team-storage model. Exact sources and changes are in SHOWDOWN_INTEGRATION.md.
- **Generated availability is authoritative.** Use pinned Showdown teambuilder generation/origin marks, including Gen 9 move resets, form ancestry, egg inheritance, Sketch and National Dex. Default selection shows the full individual pool with progressively more results; custom/all-generation choices remain available. This does not promise event/combination/tier legality or full special-mod parity.
- **Defaults never normalize an unchanged imported species.** On an explicit species change, choose a required ability, retain a valid current ability, or use normal ability 0. Fill a sole required item, offer multiple choices, and remove a former required item only when it is still held. Other set fields remain untouched.
- **Keyboard/EV semantics.** Tab/Enter commit and advance; Shift+Tab reverses and terminal movement leaves the picker. Escape returns to the field. Buttons/arrows edit EVs by four without pre-rounding odd imported values. Incomplete nature +/- choices remain local until a complete pair exists; neutral is explicit. Existing caps, Gen 1/2 mechanics and raw patching stay authoritative.
- **Canonical sprites.** Pin @pkmn/img 0.3.4 and pass shiny/gender consistently. Fix its static female-sprite edge case using its metadata, not guessed suffixes. Artwork rights remain separate from MIT/AGPL code licenses; see THIRD_PARTY_NOTICES.md.
- **New-team priority.** Display format before a generated Untitled plus short UUID title; focus Add Pokémon instead of naming. No extra database counter or library fetch. Saved naming remains editable.
- **Search typing.** Exact type words in species queries constrain actual types, so water ground excludes Water Absorb users with another type. A complete ability name still matches that ability. Global library search contracts are unchanged.
- **Source offer ships with the build.** Package tracked app/config/docs with a per-file hash manifest and a visible download link, excluding credentials, runtime environments, databases and user content. Use .tar because the dev server decodes .gz responses. Include pnpm-workspace.yaml, support rebuilding downloaded manifests without .git, and force LF for hashed generated JSON. Stage new application files before build.
- **Responsive layout.** Use gray surface levels and restrained type/category colors. Phone EV sliders have their own row. More than six imported sets remain supported; their multirow slot bar does not stick over the editor.
- **Preservation and scope.** Keep stable notes, partial/custom raw input, historical views and restore-as-new-version. No schema changes. Publication remains owner-only. PokéPaste, folders, feeds, AI, simulator, calculator, replay and collaboration are deferred to a separate request.

- **Conceptual teams stay stable.** Version creation adds an immutable snapshot, then advances the team's current pointer. Restore creates another version, preserving all newer history. parent_version_id leaves room for branching.
- **Edits are explicit snapshots.** Editing Showdown text or notes goes through Create New Version. Metadata editing changes tags, name, provenance and historical date across the conceptual team.
- **Original data is authoritative.** @pkmn/sets parses with the detected generation's Dex. Save original text plus full structured Pokémon set JSON. Retain unknown fields in export text and show warnings.
- **Bulk boundaries are explicit.** Recognize official === [format] folder/title === Showdown backup headers. A raw unheaded paste is one team. Do not guess ambiguous team boundaries or silently discard content.
- **Historical date is not import time.** Imported dates default to Unknown. Newly authored teams default to today in the user's local timezone. Exact/month/year precision is explicit; Unknown sorts last.
- **Same-set search is relational.** Pokémon-level constraints share version and slot. Metadata has its own index entries; current set records are not flattened into one six-Pokémon blob. Token indexes use B-trees; no expensive JSON scan or library-wide browser search.
- **Normal text comes first.** Maintained Dex names identify species, moves, items, abilities and natures. Explicit operators disambiguate. Species plus set attributes stay strict; species-only mentions can match notes/title. Advanced Boolean syntax and typo correction are future work.
- **Two explicit storage modes.** User confirmed no Supabase project exists yet. The connected-production adapter uses Supabase Auth/PostgreSQL/RLS. A clearly labelled, persistent, owner-scoped D1 demo makes the app usable before configuration. Configuring Supabase switches to a separate empty production library.
- **Runtime choice.** The required Sites scaffold uses React/Next App Router conventions via Vinext to emit a Cloudflare Worker. Its pinned runtime is currently beta. Production rollout should include a runtime stability review; this is disclosed rather than calling the scaffold stable Next.js.
- **Auth provider boundary.** The demo uses Sites/ChatGPT sign-in. Supabase uses magic-link email; future providers can use the same Supabase client without changing storage ownership. No service-role key is accepted or required by the app.
- **Database authorization.** All production tables have RLS; direct application-role writes are revoked. The authenticated RPC is SECURITY DEFINER with an empty search_path, explicit auth.uid checks, and private non-public helper functions. An anonymous token resolver returns a fixed shareable projection.
- **Concurrent edits.** Version saves compare the current version pointer and serialize on the PostgreSQL team row. D1 relies on atomic batches and a unique team/version-number constraint. Metadata writes reject stale database state; favourite/archive-only changes preserve current metadata.
- **Sharing is team-scoped.** Random 256-bit capability tokens authorize the conceptual team. The live link follows current; ?version=N keeps displaying a snapshot but does not restrict access to that snapshot alone. Tokens are hashed at rest and old tokens are revoked on rotation. Shared notes are escaped plain text.
- **Private deployment first.** Sites access stays owner-only. A public share audience requires an explicit later site-access change. App-level privacy remains enforced by Supabase even if the site becomes public.
- **Snapshot note storage.** Team notes and per-slot set notes live inside each immutable snapshot. They copy into versions/restores. No separate manual Pokémon labels.
- **Tags.** Normalized reusable concepts prevent case duplicates; display names retain chosen casing. Bulk application adds tags to existing tags.
- **Bounded operations (superseded 2026-09-10).** See the large-library decision below: 30 teams/page, 20 MB / 10,000-block archive preview, five-team receipt-protected write chunks and 24 sets/team. Legacy unchunked calls remain bounded at 200.
- **Deletion.** Legacy archive flags remain internally; normal UI includes those teams. Permanent team deletion has a named confirmation with Cancel focused initially. The delete predicate checks the owner in the database; existing foreign keys atomically cascade to every version, search entry, tag association and share link. Reusable account tags are retained. PostgreSQL exposes a narrowly scoped authenticated delete_team RPC through an incremental migration.
- **Visual editor.** Pokémon slots and structured fields are the primary workflow; raw text remains available. Each draft slot has a stable identity and original raw block. Only changed field lines are replaced. Implied IVs/happiness are made explicit when edits would otherwise change them. Raw rearrangement reconciles notes by exact block or unique Pokémon identity; unresolved notes require review. Saved snapshot structure and backend ownership/version APIs are unchanged.
- **Search and organisation.** Removable chips construct the existing query syntax, with from as a source alias. Format navigation groups stored IDs by generation/game and family, with generic fallbacks. Format, tags, provenance and historical date remain distinct metadata.
- **Scope.** No simulator, full legality checker, public feed or undocumented PokéPaste integration. The visual editor supports partial/custom sets and preserves advanced fields in Showdown Text.
- **Verification boundary.** Automated PostgreSQL tests exercise roles/RLS/RPCs with a local Auth shim. Live Supabase sign-in/email needs the user's project. Browser QA verified visual building, direct selectors, versions/restoration, inline metadata, set export, combined filters and tagged bulk import. Optional WebMCP calls and real touch-device behavior remain unverified. See README for the current test scope.

## Implemented Showdown UX pass — 2026-09-08

- **Reuse backend contracts.** The new direct editor, selectors and stats preserve the existing immutable snapshot, import/export, search, ownership and sharing APIs.
- **Blank creation is an unsaved draft.** New Team immediately opens Untitled team with empty slots, today's local Team Date and the active format (or unknown). Only the first nonempty save creates a record. Imported dates remain Unknown.
- **Direct editing creates versions.** A displayed field opens its slot/field/move in the version editor. Historical edits/restores create a new version using the historical parent and latest expected pointer. Shared views do not receive editing callbacks.
- **Inline metadata uses partial patches.** Save only the selected group of fields and merge only their normalized response values. Serialize metadata saves and block version creation while one is pending. Keep the displayed historical snapshot and independent favourite changes. Mutation refreshes fetch using current navigation state, abort stale responses, and clamp an emptied last page.
- **Legacy archived data remains visible.** Remove archive controls/navigation, keep stored flags, and opt normal library/facet/WebMCP queries into include_archived:true. Old API defaults remain backward-compatible. PostgreSQL changes are append-only migrations.
- **Installed catalogs and bounded selectors.** Reuse @pkmn/dex and @pkmn/sets. Filter existence, generation and nonstandard status; National Dex permits Past entries. Exclude battle-only forms from ordinary choices, but preserve imported/custom values. Display the first 100 matches with refinement controls. No item sprites were added.
- **Learnsets are suggestions.** Generation/source and form/pre-evolution inheritance provide useful ranking/filtering, not event/transfer/combination legality. Smeargle is an approximation. Cache by normalized format and species so National Dex availability does not leak between formats.
- **Stats are ordinary unboosted values.** Exclude battle/item/ability effects. Modern edits use 252 per stat and 510 total; Gen 1/2 use DV/stat-experience equivalents and no modern total cap. Gen 1 displays one Special stat. Preserve explicit zero old-generation stat experience and unsupported raw fields. Builder and parser share generation detection.
- **Raw preservation remains mandatory.** Unknown lines, implied Hidden Power IVs/Frustration happiness, stable note identities, orphan-note review, partial sets and immutable history survive editing. Export set uses the displayed snapshot's raw block; unsafe layouts require full export.
- **Explicit note filters cover current notes.** note: matches current team or set-note words across the team; quoted values are ANDed words, not phrases. Older set-note tokens are excluded unless restored into a new current version. Species/move/item/ability matching remains strict on the same set. No reindex is required.
- **Navigation and density.** Default to compact list only when no valid saved view exists. Keep All Teams/Favourites, automatic Formats and Settings. Tags, source and dates live in global search and contextual metadata. User tags named Archive remain ordinary tags.
- **Scope remains bounded.** No PokéPaste, folders, shared folders, feeds, damage calculator, AI, replay analysis, collaboration or perfect legality. Full desktop/phone acceptance and hosted Supabase verification remain follow-ups; see PROGRESS.md.

## Large-library foundation — 2026-09-10 (historical checkpoint; invariants retained)

- Formats use the pinned official Showdown registry at cc089d36b7717dec78ce8ab5d1745c03ad5c97e4. Picker choices save canonical IDs; names are display only. Use Singles/Doubles, then generation/game, then format. National Dex remains in its battle type. Bare names without context use current Gen 9; explicit historical context wins. Unknown imports retain their string, and Custom / Other stores generation/battle metadata with incomplete-assistance wording. This does not add simulator or special-format parity.
- Never rewrite old raw snapshots merely to normalize a format. Alias-aware searches cover old recognized spellings. Format context affects parsing/builder/read-only presentation, not historical raw bytes.
- 10,000 teams is a measured target, with 30 full current snapshots per page. Materialize selected page IDs before snapshot joins; anchor same-set candidate lookup. Facets aggregate in SQL and refresh separately from query/page changes. Do not replace this with browser library scans.
- Parse one bounded archive, show 50 previews/page, then save five teams per chunk. All chunks have owner-scoped operation ID/index, request digest and result receipt. A receipt and its mutations commit together. Replay returns original results; changed payload reuse fails. Retain successful chunks after failure and retry the rest. Closing/reloading a paused dialog loses UI resumption state, so communicate that boundary; a fresh import is intentionally distinct.
- Bulk Add tag and Delete use the same receipt model. D1 now preflights every target and commits a chunk atomically, including concurrency checks. PostgreSQL checks owners and locks rows. One delete confirmation covers the selected count; never confirm each team separately. While selecting all results, block bulk actions until the final authorized ID count arrives. Partial completion reports its actual count.
- Group D1 search/tag inserts using JSON table expansion to reduce statements without weakening stale-write/history guards. Local timings are not hosted latency claims; see PERFORMANCE.md.
- At that historical foundation checkpoint, families/variants and collections were designed but not yet installed. Both are now implemented; SCHEMA_PLAN.md documents their additive migrations. History has not been renamed to variants. Existing team shares retain their current semantics. Folders, PokéPaste publishing and special-format parity remain excluded.

# Collections and measured Save work — 2026-09-10

- A Collection is a private named saved search, not a folder or duplicated team membership. Store definition v1 (canonical query/filter chips, favourites, sort and a server-compiled plan). Names are unique per owner ignoring case; edits/deletes compare updated_at. Stable client-generated IDs make a repeated identical creation safe.
- collection_shares stores only 256-bit token hashes, mode live, and revoke timestamps. Live resolution loads the owner and saved plan through the capability each request. Page/family/team IDs only narrow selection. Public output exposes matching current variants grouped by family, their notes/provenance and matching counts; it excludes history, nonmatching siblings, private counts, saved definitions and private authoring state. Standalone variant sharing retains its existing numbered-history semantics.
- PostgreSQL uses one revoked owner-parameterized grouped-query helper for both authenticated libraries and the capability resolver, without impersonating an auth context. Collection writes serialize per owner independently of team writes. RLS exposes only the owner's collection records; share rows and private helpers are not directly callable. D1 always supplies owner predicates. Deleting a collection cascades share rows and never deletes teams.
- Future snapshot collections require explicit immutable membership/snapshot records. Do not silently treat live links as snapshots. The existing owner-only Sites access gate remains unchanged.
- Save profiling is opt-in via profile=1 and numeric Server-Timing headers. The browser keeps at most 60 local traces, containing durations/action/set count only. D1 mutation timing measures the awaited batch, not an invented hosted database CPU time; Supabase's RPC stage includes network. Browser visible timing is a post-commit animation-frame/timer checkpoint, not a physical-display measurement.
- D1 get now uses a single statement for current/history/share status, improving consistency and removing sequential round trips. Hidden library/facet refreshes wait until the library is shown; initial sidebar facets still load. Existing returned saved DTOs update details immediately after persistence. Preserve current/history/restore guards and exact raw snapshots.
- New collection dialogs stay mounted outside the mobile sidebar and portal only their navigation into it. This keeps Save as collection and management accessible with the sidebar closed. Search-filter buttons explicitly use type=button inside the collection form. Sign-in and back navigation retain deep links / the opt-in profile parameter.
- Browser before/after medians improved, but localhost HTTP-only medians did not uniformly improve and Saving feedback still has render variability. Report both datasets; no hosted latency guarantee or claim that all outliers are solved.
